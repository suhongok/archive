# ROS2 콜백 방식 동작 원리

## 🎯 핵심 개념

**콜백 방식은 서비스 응답 전까지 콜백이 실행되지 않습니다.**

- ✅ 요청 전송 ← 즉시 완료
- ✅ 콜백 등록 ← 즉시 완료
- ⏳ 응답 대기 ← 콜백 **미실행**
- 🔔 응답 수신 ← 콜백 **자동 실행**

---

## ⏱️ 콜백 방식의 시간 흐름

### 타임라인

```
시간 →

[1] 요청 전송
    ↓ (비동기 - 즉시 반환)
[2] 콜백 등록
    ↓ (즉시 완료)
[3] "요청 전송 완료" 출력
    ↓
[4] while 루프 진입
    ↓
[5] spin_once() 실행 ← 응답 받을 준비
    ↓
[6] "백그라운드에서 이 코드 계속 실행 중..." 출력
    ↓
    ... 대기 중 ...
    ↓
[7] 서버가 응답 전송
    ↓
[8] ROS2가 응답 수신 감지
    ↓
[9] 콜백 함수 자동 실행 ✨
    ↓
[10] 응답 처리
```

## 💻 실제 코드 예시

```python
def callback(future):
    """서버 응답 후 자동으로 실행됨"""
    try:
        response = future.result()
        print(f"✅ 콜백 실행됨! 응답: {response}")
    except Exception as e:
        print(f"❌ 실패: {e}")

# ========== 이 부분이 즉시 실행됨 ==========
print("1. 요청 전송 시작")
self.future = self.client.call_async(self.req)

print("2. 콜백 등록")
self.future.add_done_callback(callback)  # ← 등록만 함, 실행 안 함

print("3. 요청 전송 완료")  # ← 즉시 출력됨
# 여기까지 빠르게 실행

# ========== while 루프 ==========
while rclpy.ok():
    rclpy.spin_once(node)
    print("4. 백그라운드에서 이 코드 계속 실행 중...")  # ← 계속 출력
    
    # 콜백은 여기서 언제든지 자동 실행됨
    # 서버가 응답하는 순간 "✅ 콜백 실행됨!" 출력
```

### 출력 순서

```
1. 요청 전송 시작
2. 콜백 등록
3. 요청 전송 완료
4. 백그라운드에서 이 코드 계속 실행 중...
4. 백그라운드에서 이 코드 계속 실행 중...
4. 백그라운드에서 이 코드 계속 실행 중...
✅ 콜백 실행됨! 응답: ... (이 시점은 서버 응답 속도에 따라 달라짐)
4. 백그라운드에서 이 코드 계속 실행 중...
```

## 🔄 서버 응답 전 vs 후

### 서버 응답 **전**
```python
self.future = self.client.call_async(self.req)
self.future.add_done_callback(callback)

# 이 시점에 콜백은:
# ❌ 등록됨
# ❌ 실행 안 됨
# ❌ future.result() 접근 불가

# 다만 future 객체는 존재함
print(self.future)  # <Future object>
```

### 서버 응답 **후**
```python
# ROS2 네트워크에서 응답 도착 감지
# ↓
# callback() 자동 실행

def callback(future):
    # ✅ 콜백 실행됨
    # ✅ future.result() 접근 가능
    response = future.result()  # ← 이제 값 있음
```

---

## 📊 상태 변화 테이블

| 시점 | future.done() | 콜백 | result() |
|------|-------------|------|---------|
| **요청 직후** | False | 미등록 | 불가 |
| **콜백 등록 직후** | False | 등록됨 | 불가 |
| **대기 중** | False | 대기중 | 불가 |
| **응답 수신** | True | 실행됨 | 가능 ✅ |

## ✨ 핵심 특징

### 언제 콜백이 실행되나?

```python
# ❌ 이 시점에는 실행 안 됨
self.future.add_done_callback(callback)

# ❌ 이 시점에도 실행 안 됨
print("대기 중...")

# ⏳ 이 시점에도 실행 안 됨
while rclpy.ok():
    print("계속 대기...")

# ✅ 이 시점에 자동 실행!
# "서버가 응답을 보냈을 때"
```

### 다른 작업과의 관계

```python
self.future.add_done_callback(callback)

# 콜백이 등록되었지만, 아직 실행되지 않음
while rclpy.ok():
    rclpy.spin_once(node)
    
    # 이 코드는 콜백 실행 전/후로 계속 실행됨
    print("메인 루프 계속 실행")
    
    # 콜백은 별도로 실행됨 (ROS2 이벤트 루프에서)
```

## 🎓 결론

| 질문 | 답변 |
|------|------|
| **콜백은 언제 등록되나?** | `add_done_callback()` 호출 시 **즉시** |
| **콜백은 언제 실행되나?** | 서버가 **응답을 보낼 때** |
| **응답 전에 다른 코드 실행?** | ✅ 예, 콜백 실행 대기 중에도 계속 실행 |
| **응답 받으면 콜백 자동 실행?** | ✅ 예, ROS2가 자동으로 호출 |
| **여러 요청 가능?** | ✅ 예, 각각의 future에 콜백 등록 |
