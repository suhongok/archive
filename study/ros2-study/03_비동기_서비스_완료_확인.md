# 비동기 서비스 완료 여부 확인 방법

## 📌 개요

ROS2에서 비동기 서비스(`call_async()`)를 호출할 때, 서버의 응답을 확인하는 **3가지 방법**이 있습니다.

---

## 1️⃣ `future.done()` 메서드 (폴링 방식)

### 원리
- 주기적으로 `future.done()`을 호출하여 완료 여부 확인
- **Boolean** 반환: True (완료), False (대기 중)
- while 루프에서 계속 체크

### 코드 예시
```python
self.future = self.client.call_async(self.req)

while rclpy.ok():
    rclpy.spin_once(empty_client, timeout_sec=0.1)
    
    # 완료 여부 확인
    if empty_client.future.done():
        try:
            response = empty_client.future.result()
            print(f"Success: {response}")
        except Exception as e:
            print(f"Failed: {e}")
        break
    
    # 응답 대기 중 다른 작업 수행
    print("additional work...")
```

### 특징

| 장점 | 단점 |
|------|------|
| 간단하고 직관적 | 계속 폴링해야 함 (CPU 사용) |
| 실시간으로 상태 확인 | 응답 체크 주기에 의존 |
| 응답 중 다른 작업 가능 | - |

### 사용 상황
- 간단한 단일 요청
- 응답 대기 중 다른 작업 필요
- 현재 코드 방식

---

## 2️⃣ `future.add_done_callback()` (콜백 방식)

### 원리
- 서비스 완료 시 **자동으로 콜백 함수 호출**
- 이벤트 기반 처리
- 폴링이 아닌 푸시(push) 방식

### 코드 예시
```python
def callback(future):
    """서버가 응답할 때 자동으로 실행됨"""
    try:
        response = future.result()
        print(f"Success: {response}")
    except Exception as e:
        print(f"Failed: {e}")

# 콜백 등록
self.future = self.client.call_async(self.req)
self.future.add_done_callback(callback)

# 콜백이 등록되었지만 아직 실행 안 됨
print("요청 전송 완료")

# 일반적인 ROS2 루프
while rclpy.ok():
    rclpy.spin_once(node)
    # 콜백은 여기서 자동으로 실행됨
```

### 타임라인
```
시간 →

[요청 전송]
    ↓
[콜백 등록]
    ↓
[대기 중] → spin_once() 실행
           → 다른 작업 수행
    ↓
[서버 응답 수신] ← 네트워크에서 도착
    ↓
[콜백 자동 실행] ← ROS2가 자동으로 호출
    ↓
[결과 처리]
```

### 특징

| 장점 | 단점 |
|------|------|
| 이벤트 기반으로 효율적 | 콜백 함수 정의 필요 |
| 폴링 없음 (CPU 절약) | 복수 요청 시 콜백 관리 필요 |
| 응답 즉시 처리 | 콜백 체이닝 복잡할 수 있음 |

### 사용 상황
- 여러 개의 서비스 요청 동시 처리
- CPU 절약 필요
- 복수의 이벤트 기반 처리

---

## 3️⃣ `rclpy.spin_until_future_complete()` (대기 방식)

### 원리
- future 완료까지 **완전 블로킹** 대기
- 타임아웃 설정 가능
- 단순하고 명확한 대기

### 코드 예시
```python
self.future = self.client.call_async(self.req)

# future 완료까지 대기 (최대 5초)
rclpy.spin_until_future_complete(
    node, 
    self.future, 
    timeout_sec=5.0
)

# 이제 응답을 받은 상태
try:
    response = self.future.result()
    print(f"Success: {response}")
except Exception as e:
    print(f"Failed: {e}")
```

### 특징

| 장점 | 단점 |
|------|------|
| 가장 간단함 | 완전 블로킹 (다른 작업 불가) |
| 명확한 대기 로직 | 응답 대기 중 멈춤 |
| 타임아웃 지원 | 응답 중 GUI 반응 불가 |

### 사용 상황
- 단순 동기적 대기
- 응답 후 진행하는 직렬 처리
- GUI가 없는 백그라운드 처리

---

## 📊 세 가지 방식 비교

| 기준 | done() | add_done_callback() | spin_until_future_complete() |
|------|--------|-------------------|----------------------------|
| **동작 방식** | 폴링 | 이벤트 | 블로킹 |
| **블로킹 여부** | 아니오 | 아니오 | 예 |
| **CPU 효율** | 낮음 | 높음 | 높음 |
| **구현 복잡도** | 낮음 | 중간 | 낮음 |
| **응답 중 작업** | 가능 | 가능 | 불가능 |
| **복수 요청** | 부적합 | 적합 | 부적합 |

---

## 💡 추천 사용 방식

### 상황별 추천

| 상황 | 추천 방식 | 이유 |
|------|---------|------|
| **단순 단일 요청** | `spin_until_future_complete()` | 가장 간단하고 명확 |
| **응답 대기 중 작업 필요** | `done()` | 폴링으로 다른 작업 병렬 처리 |
| **여러 요청 동시 처리** | `add_done_callback()` | 이벤트 기반으로 효율적 |
| **GUI 응답성 중요** | `add_done_callback()` | UI 블로킹 없음 |
| **간단한 백그라운드 처리** | `spin_until_future_complete()` | 직관적이고 유지보수 용이 |

---

## ✨ 현재 코드 분석

```python
# done() 방식 사용
if empty_client.future.done():
    response = empty_client.future.result()
```

**장점:**
- 응답 대기 중 `'additional work...!'` 로그 출력 가능
- 다른 작업과 동시에 처리
- 직관적인 구현

**개선 여지:**
- 폴링 방식이므로 CPU 약간 사용
- 여러 요청이 필요하면 콜백 방식 고려
